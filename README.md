## Overview

### The field problem

Baghewala produces heavy crude (about 17–19° API) from the Jodhpur Sandstone reservoir. High oil viscosity, low reservoir pressure and temperature, and declining heat after steam injection can limit oil mobility. CSS cycle design and sucker rod pump (SRP) settings are often considered separately, even though reservoir temperature and viscosity affect pump loading, energy use, and operating risk.

### What this repository provides

This project is a **working software prototype** of an integrated well-to-surface workflow. A React and TypeScript frontend calls a FastAPI backend that advances simplified per-well demonstration models. The model links reservoir temperature to estimated viscosity, wellbore profiles, rod and dynamometer behavior, surface estimates, and production flow. Operators can inspect simulated conditions, review model-generated insights, and compare CSS or SRP what-if cases.

The application is **not connected to Oil India field sensors, SCADA, or physical pumps**. Its telemetry and well conditions are generated by demo models, not the field datasets described in the SIH problem statement. The AI Insights page uses model rules and simulated classifier outputs; it is not a trained or field-validated PINN. CSS and pump optimizations are prototype calculations, not approved operating instructions. See the [Prototype Guide](PROTOTYPE_GUIDE.md) for the page-by-page walkthrough and limitations.

## Key Features

### 🧠 Integrated demonstration model
- Connects simplified thermal decline, temperature-dependent viscosity, wellbore profiles, rod dynamics, dynamometer, surface estimates, and Darcy-style flow calculations.
- Provides threshold/model-based insights and simulated rod-float or impact-risk estimates; these are illustrative, not field-validated predictions.

### 📊 Well monitoring and visualisation
- Per-well demo telemetry is served by FastAPI and displayed in Live Data charts; REST polling is used when WebSocket streaming is unavailable.
- Reservoir, wellbore, pumpjack, and depth views help users explore model values. 3D geometry is illustrative, not a live field visualization.

### 🧪 What-if analysis
- Simulation and CSS pages compare alternative model inputs without applying those what-if results to the selected well.
- Pump Control changes the selected **simulated** well state so other pages can show updated demo values. It does not control physical equipment.
- Optimization compares candidate simulated pump speeds against selected objectives; the result is a recommendation, not an automatic control action.

### 🚨 Alerts and reporting
- Alerts display model-generated threshold conditions and browser-local demo notifications.
- Reports export a current snapshot as CSV or open the browser print dialog for PDF. They do not query a historical production database.

### 👥 Prototype access and demo surfaces
- The app includes login, supervisor, and well-incharge screens to demonstrate different workflows. Authentication, account management, fleet cards, and several settings/history panels are prototype or mock behavior—not production security or operational systems.

## Local Setup

### Prerequisites

| Requirement | Minimum Version |
|---|---|
| Node.js | 18.x |
| Python | 3.8 |

---

### 1. Clone the Repository

```bash
git clone https://github.com/qwertypoiuy9/sih-120-final.git
cd sih-120-final
```

---

### 2. Backend Setup

```bash
cd backend

# Create and activate a virtual environment
python -m venv venv

# Windows
venv\Scripts\activate

# macOS / Linux
source venv/bin/activate
```

**Option A — Full installation (requires PostgreSQL):**
```bash
pip install -r requirements.txt
```

**Option B — Demo mode (no database required, recommended for quick start):**
```bash
pip install -r requirements-demo.txt
```

**Configure environment variables:**
```bash
# Create backend/.env
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/baghewala_digital_twin
```
> If you skip this, the backend auto-runs in demo mode with in-memory simulation.

**Start the backend:**
```bash
# From the backend/ directory
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

Backend is live at → `http://localhost:8000`  
Interactive API docs → `http://localhost:8000/docs`

---

### 3. Frontend Setup

```bash
# From the repo root
cd frontend

# Install dependencies
npm install
```

**Configure environment variables:**
```bash
# Create frontend/.env
VITE_API_URL=http://localhost:8000
VITE_WS_URL=ws://localhost:8000/ws/digital-twin
```

**Start the dev server:**
```bash
npm run dev
```

Frontend is live at → `http://localhost:5173`

---

### 4. Docker Deployment

This project also supports containerized deployment with Docker Compose.

```bash

docker compose up --build
```

This starts:
- Backend API at `http://localhost:8000`
- Frontend at `http://localhost:5173`
- PostgreSQL at `localhost:5432`

Use the same demo credentials listed below after the containers start.

## Demo Scenarios

The Overview page includes six presets for demonstrating how the simulated model responds. Selecting a preset changes simulated state; it is not a physical CSS or pump operation.

| Scenario | Trigger Condition | What to Watch |
|---|---|---|
| **Normal Production** | Baseline demo preset | Resets simulated temperature, speed, and scenario classification |
| **Reservoir Cooling** | Cooler preset condition | Demonstrates downstream changes in viscosity and model state |
| **High Viscosity** | Higher-viscosity preset condition | Demonstrates how the model and risk display respond |
| **Rod Float** | Rod-float scenario preset | Demonstrates classifier output and related simulated alerts |
| **Impact Loading** | Impact-loading scenario preset | Demonstrates classifier output for a different simulated condition |
| **Optimized Operation** | Alternative speed/temperature preset | Illustrates a candidate state; it is not field-validated or automatically optimized |

Scenario labels and resulting values are demonstrations, not measured field events or guaranteed alarm thresholds.

## ⚠️ Disclaimer

This is a **demonstration prototype** for the Smart India Hackathon problem statement.

- Telemetry and well conditions are simulated; there is no connection to Oil India field sensors or SCADA.
- Pump Control changes simulated state only. No VFD commands or other equipment writes are made.
- The thermal, viscosity, wellbore, rod, risk, and production calculations are simplified demonstrations and are not field-calibrated.
- Insights and optimization results are not trained, field-validated AI predictions or approved operating instructions.
- History, parts of Settings and Alerts, and supervisor fleet values are static, mock, or browser-local demo behavior.
- Login and user management are not production-grade authentication or authorization.
